Automatic blocking on the Blocking tab

These are the app's real screens with your Jeffco Westracks project loaded, drawn with the app's own styles. The blocks in Screens 3 and 4 are real: I generated them with the rules shown, loaded them into the app as a blocking scenario, and captured what the Blocking and Costing tabs display. Marked elements are proposed; everything else is the current app.

Screen 1 · Blocking tab

Start at Federal Center, Saturday, with no blocks yet

The blocking scenario Actions menu, opened from the "…" at the right of the scope bar. The unassigned trips list is cut to its first rows.

  1. 1
    Build blocks automatically…

    A new item in the Blocking scenario group. It creates a new blocking scenario and never changes an existing one. A day-level version, "Block unassigned trips automatically…", could later go in the Blocks panel's "…" menu to finish a partly hand-built day.

Screen 2 · Dialog, as it opens

Build blocks automatically

The rules are in sections on the left. Patterns and Breaks open by default because every project uses them. The three rarer sections stay closed and show a one-line summary, so the dialog stays short unless you need them. The right column stays in view: rules read from built blocks, then a live preview.

  1. 2
    Patterns, grouped by direction

    One table per direction group, with one row per pattern used by the trip profile. Each row sets the minimum layover after a trip on that pattern (none, minutes, or % of the trip) and whether a break can be taken there.

  2. 3
    Where a block can start and end

    Per pattern: whether a block may begin with a trip on this pattern, and whether it may end after one. Here blocks start only on To Morrison and end only on To JeffCo, so every block starts and ends at Federal Center.

  3. 4
    Breaks: one rule for short and long blocks

    Blocks under the minimum length get no break. Longer blocks get a first break no earlier than the set time, then another each time they run the set hours without one. A worked line shows what the rule means for 4, 8 and 16 h blocks.

  4. 5
    Closed sections with summaries

    Block limits, Pull-out and pull-in, and Deadhead connections each show what they currently do. Screen 2b shows them open.

  5. 6
    Read rules from built blocks

    Measures a built blocking scenario anywhere in the project and fills matching rows: patterns with the same name first, otherwise by direction group. Each row it fills is listed, so nothing changes silently.

  6. 7
    Preview and check

    Updates as you type. It counts blocks with one break and with two, and runs the same rules on the source scenario to compare with its built blocks.

Screen 2b · Dialog, rarer sections open

Block limits, pull-out and pull-in, deadhead connections

Only the left column is shown. None of these is needed for Federal Center, so each is at its default.

  1. 8
    Block limits

    Maximum running hours and maximum revenue miles per block. When adding a trip would go over a limit, a new block starts. Revenue miles is disabled while any pattern's miles are incomplete, as they are in this project.

  2. 9
    Pull-out and pull-in

    Choose a garage node, or none (the block starts and ends at a terminal). One row per terminal where a block can start or end, with minutes and miles. These become the ordinary pull-out and pull-in rows of each block.

  3. 10
    Deadhead connections

    Rules of the form "a vehicle can deadhead from A to B in X minutes", as many as you need, one way or both ways. A connection is used only when it lets a block take a later trip, and it becomes an ordinary deadhead row. In East Side, GreenMtn → 1_JeffCo would fix the broken chain.

Screen 3 · Blocking tab

The new blocking scenario, Saturday

Nine real blocks generated with the rules in Screen 2: 58.80 revenue hours and a 24.4% layover share. The Block 7 detail shows the 43-minute layovers at Federal Center.

  1. 11
    How it was built

    A note stored with the blocking scenario records the rules and the date, and whether any block has been edited since. "Rebuild…" reopens the dialog with those rules. Because it replaces the blocks, it confirms first and names any edited blocks it would discard.

Screen 4 · Costing tab

Costing with the automatic blocking scenario

Unchanged from today's app. The new blocking scenario appears in the Cost basis list under Blocked hours, and costs exactly like hand-built blocks.

  1. 12
    No new cost basis

    "Blocked · Automatic · 20 min in, 35 min break" gives 9 blocks a day and $251,942 in 2026. The Estimate factors panel keeps its current size, so the white space problem doesn't arise.
